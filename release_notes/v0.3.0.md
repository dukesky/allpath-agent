# Allpath Agent v0.3.0

Released: 2026-08-02

Allpath Agent v0.3.0 ships two things: the first structured, approval-gated
browser capability, and the completion of the onboarding teaching surfaces so
progressive capability learning actually reaches every live installation. It
also opens the next phase plan whose destination is one end-to-end golden
path: connect a model, connect Telegram, schedule a daily briefing in
conversation, and receive it the next morning.

## Highlights

### Structured browser

- Navigate public websites through Playwright with a dedicated, isolated
  Chrome/Chromium profile (`~/.allpath-agent/browser-profile`, owner-only
  permissions) so Agent cookies and downloads never mix with the user's own
  browser.
- Public-network URL enforcement everywhere: scheme and credential checks,
  DNS resolution with non-global address rejection, re-validation after
  redirects and clicks, and per-subresource request filtering. Local and
  internal addresses are refused by design.
- Bounded structured snapshots instead of raw pixels: visible interactive
  elements receive stable `e1…eN` references with role, name, and
  query-stripped links, capped in element count and text size.
- Approval-gated `browser_click` and `browser_type` actions; navigation and
  clicks return a fresh snapshot so the model never acts on stale page state.
  Typed text is redacted from approval previews, audit records, and results.
- Approval-gated `browser_screenshot` and `browser_download` write to
  private fixed directories with unique filenames, owner-only permissions,
  and size limits; the model cannot choose output paths, and page-initiated
  downloads outside an approved call are cancelled.
- Self-service setup: `/browser status|test|install|reset` reports runtime
  readiness with the exact next action, verifies real navigation, installs
  Chromium after approval, and resets only Allpath's own isolated profile.
  Natural-language requests like “configure browser” reach the same flow.

### Onboarding funnel completion

- The live launch card is now curriculum-driven. Previously it demanded that
  Telegram, Slack, and WhatsApp all be configured before any capability
  lesson could appear, so most installations never saw curriculum guidance.
  Now one active messaging connector — or an explicit
  `/dismiss messaging_connectors` — advances startup guidance to the next
  unlearned capability.
- The composer hint is connected to curriculum state. When no setup workflow
  needs input, an idle live session shows the next unlearned capability
  action beside the input area, and connector state is re-read every prompt
  so the hint advances immediately after a mid-session connection.
- A shared hint selector now drives both surfaces with one ordering and one
  learned-status rule, and suppressed or dismissed capabilities never appear
  in either surface.
- Successful `browser_screenshot` and `browser_download` executions now count
  as verified `browser_tasks` curriculum evidence, so browser tasks completed
  through artifacts advance learning progress like every other capability.
- The deterministic inputs of curriculum progress — intent detection and
  task-evidence derivation — received their first direct unit tests.

### Direction

- `docs/NEXT_PHASE_PLAN.md` was rewritten after a full project review. The
  next phase closes the gap between what the curriculum teaches and what a
  user can complete: conversational automation creation, unattended
  execution inside the gateway, delivery of automation results to messaging
  connectors, a read-only web lookup tool, and a daily-briefing golden path.
- Stale documentation was corrected: the browser boundary document and the
  evolution plan acknowledge the shipped structured browser, and the README
  onboarding sequence no longer lists an unshipped WeChat connector.

## Safety boundaries

- The browser refuses non-public addresses at navigation, redirect, click,
  and subresource level, and runs in an isolated profile that can be reset
  without touching user data.
- All page-mutating browser actions, screenshots, downloads, and runtime
  installation remain approval-gated side effects with audited, redacted
  arguments.
- Curriculum state continues to stay out of the model system prompt; hints
  render only in the terminal UI.

## Validation

- 220 standard-library unit and integration tests pass locally.
- New coverage: hint selection and ordering, dismissal and suppression
  behavior, browser artifact evidence, intent detection in English and
  Chinese, and task-evidence derivation against a real temporary SQLite
  database.
- A live-switch CLI test now asserts the curriculum composer hint appears
  after a conversation-driven model connection.
