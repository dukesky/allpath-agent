# Allpath Agent v0.4.0

Released: 2026-08-02

Allpath Agent v0.4.0 completes the golden path the project was founded on:
install → connect a model in conversation → connect Telegram → say
“create automation” to schedule a daily briefing → receive it in Telegram the
next morning. Every step is now real, guided, and covered by a deterministic
end-to-end test.

## Highlights

### Automations become real

- Conversational creation: say “create automation” (or `/automations add`)
  and Allpath collects the name, task, schedule (five-field cron or one-time
  ISO time, validated as you type), timezone, and delivery destination, then
  echoes the full summary and saves only after an explicit “confirm”. The
  flow is bilingual, resumable across restarts, and supports back, status,
  and cancel at every step.
- Unattended execution: the gateway — foreground `allpath-agent gateway` or
  the installed background service — drains due jobs after each connector
  poll. No external cron invocation of `tick` is needed anymore.
- Connector delivery: jobs with an explicitly configured destination send
  their results through the connected channel and record the delivered
  message ID. A delivery failure marks the run failed while retaining the
  generated output.
- A safe unattended policy: side-effecting tools stay default-denied; a
  denied request marks the run “needs attention” in run records, gateway
  output, and CLI output instead of failing silently.
- Destinations are chosen from conversations Allpath has already seen —
  message your bot once and it becomes a selectable delivery target.

### Web lookup

- A read-only `web_lookup` tool fetches one public page and returns bounded
  extracted text: public-network validation on the initial URL and on every
  redirect hop, capped body reads, script/style-free HTML text extraction,
  and truncated output. No browser installation is required, and no approval
  prompt interrupts read-only lookups — matching the structured browser's
  read/act boundary.

### The golden path, taught and tested

- Daily briefing is the sixteenth curriculum capability. As soon as the
  first messaging connector is active, the launch card and composer hint
  advance to it: “Try: create automation — a daily briefing to your
  channel.” Success is evidenced deterministically when a cron automation
  with a delivery destination is saved.
- A deterministic integration test walks the entire path with fake
  transports: fresh home → fake live model → seeded Telegram → briefing
  created through the real chat CLI → forced-due tick → the briefing message
  asserted inside a fake Telegram transport, including the recorded
  delivered-message ID.
- The README now opens with the golden-path quickstart, and the validation
  guide documents the one remaining user-assisted checkpoint: a real-account
  Telegram briefing smoke test.

### Correctness hardening

- Unattended automation runs no longer touch curriculum state at all — no
  phantom capability offers, no suggestion rows in automation sessions, no
  cooldown erosion. Only interactive conversations teach.
- Automations with schedules that no longer parse are disabled with their
  history retained instead of crashing the gateway runner.
- Local-only automations keep running from `automations run`/`tick` even
  when an unrelated connector's secrets are missing.
- `needs_attention` is a proper boolean across all run-record reads.

## Safety boundaries

- Nothing is saved from the creation flow before the user confirms the
  echoed summary; no secrets are involved anywhere in it.
- Delivery requires both a destination connector and conversation configured
  explicitly on the job; results never leave the machine otherwise.
- `web_lookup` refuses local and private-network addresses at every hop and
  never executes page scripts.
- Curriculum state continues to stay out of the model system prompt.

## Validation

- 259 standard-library unit and integration tests pass locally.
- New coverage: schedule/timezone/destination validation and resume behavior
  of the creation workflow, delivery success/failure/needs-attention paths,
  gateway drain semantics, web_lookup security and extraction bounds, daily
  briefing hints and evidence (positive and negative), curriculum
  suppression for unattended runs, and the full golden-path walk against
  fake transports.
